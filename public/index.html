Atom spotlight

Give your agent a paintbrush

agent_sketchpad lets a tool-calling agent draw with an ordered list of SVG strokes, one update per shape. The drawing next to this text is a real, cached run of a live sketch agent: all 13 strokes, replayed as the agent sent them, from the prompt “a robot painting a watercolour of a robot painting on a canvas”.

How the drawing stays safe

Creative freedom inside a fence it can't climb. Every stroke is parsed with a real XML parser and re-validated server-side before it's embedded, never trusted as a string just because the agent already checked its own output. A fixed allowlist: 8 SVG element types and 24 attributes, no others accepted, so no onclick and no event handlers of any kind. Attribute values are restricted to a safe character class with no colon, which rules out javascript: and every other URI-scheme trick in one move. Malformed or disallowed elements are skipped with a warning, not a crash. A canvas holds at most 250 elements, so nothing pathological gets embedded either.

  • Real XML parser, not regex
  • 8-tag, 24-attribute allowlist
  • No colon in values, so no javascript:
  • 250-element cap
  • Fails safe, not loud

Background

What a catalog does

A2UI is an open protocol from Google for AI agents to describe a user interface as data, a list of typed components, that a client then draws.

A catalog defines the component types an agent may use, so the 7 renderers draw consistent interfaces on the web, in MCP hosts and on Android. The same atoms also reach Google Workspace, Google Slides and PowerPoint.

We maintain A2UI Atomic Catalog as an independent, unofficial open catalog. Watch the introduction film on our guide page or inspect examples in the demo gallery.

Under the hood

What is an A2UI catalog?

In the A2UI protocol, a catalog is the set of component types an agent is allowed to use, identified by a catalogId URL. An agent doesn't invent UI: it composes from the catalog it has been given. This site is exactly that, the A2UI Atomic Catalog, an independent, open catalog of typed atoms published as plain JSON any agent can resolve.

One base catalog, many extensions

a2ui-atoms-v1 is always resolved: structure, text, inputs, actions, wired state. Extension catalogs (charts, booking, effects, editorial, ops…) each declare a when-to-use, so an agent picks by need, not by recall.

Discovered, not memorized

Over MCP: list_catalogs → get_catalog → render_surface. In the other direction, required_catalogs tells you which catalogs a payload depends on. Atoms are never registered as individual tools.

Plain files, real URLs

Every catalog is a JSON file under /catalogue/, and the index lists them all with their when-to-use text. The same catalog IDs work on the web, in MCP Apps, in Google Chat and in Apps Script.

Not repeatable from this page yet. The agent code is not published, so there is nothing here to deploy. The card and prompts below are the ones we used.

  1. Host the agent at an https address you control. The code is not published yet; see Get the code below.
  2. Type your service address below, copy the agent card, and paste it into Custom agent via A2A in your app.

Other renderers React, Lit, Angular and CopilotKit: what happened in one test, and what we did not test.

What each renderer did with the stored card

One trial per row. Rows marked 17 November 2026 were run on the fixed cards; the others are from 16 November 2026. An offline test harness: headless Chromium, files opened locally, network off, a fresh profile. The card is the stored login example: 15 Text components and 1 Image (the diagram as an SVG data URL, 1004 by 341 pixels, with its description as the alt text). The 17 November runs used Playwright with headless Chromium, pages served from the test machine itself, every request leaving it or its local network aborted (none tried). The cards are built by our agent code: a v0.9 card with the official catalog id, the same card with CopilotKit's id, and a v1.0 card.

Not verified

  • The full CopilotKit chat stack (provider, message renderer, dev server): only its shipped renderer package was driven, offline.
  • Angular and Lit used the harness's markdown settings, not what a production host would configure.
  • A v1.0 result for Angular and Lit: the v1.0 card was run on React and CopilotKit only.
  • How each host delivers the card in real use.
  • The 17 November runs drove the renderer packages directly, not a host. Version v0.9.1 and the full CopilotKit chat stack were not run.
  • Which card a host gets: our agent picks the v1.0 card only when the host offers the v1.0 Basic catalog and no v0.9 one.

Each renderer matches the catalog id exactly, so an agent should read the ids the host lists and pick one of them.

A2UI Example: A Trip Planner Built with the Basic Catalog

A2UI is an open protocol created by Google that lets an AI agent show real interface. This example shows how far you can go with its Basic Catalog, the standard set of 18 components and 14 functions. Unofficial, and not affiliated with Google.

Try it

Say where you are going and on which dates, or leave Lisbon as it is. Each number marks a part of the screen, and the list names it and links to its page. The bar shows where the time went, in the order it happened.

No script? The parts, the numbers and a sample message are below.

The parts

One request for Oslo, 3 days (Basic components only, text version) produced 32 parts, all from the Basic Catalog:

Basic components in the trip planner (text version)
ComponentPartsWhat it does here
Text17the title, the dates line, the place description, the section headings, each day's date, temperatures and rain chance, and the local time
Row4one row per day (date, temperature range, rain chance) and the row of two buttons
CheckBox4the packing checklist, one box per suggested item
Column2the stack that lays the brief out top to bottom (plus the outer wrapper)
Divider2the lines that separate the weather from the pack list
Button2Save plan and Change dates; pressing one sends an action to the agent
Card1the card that holds the whole brief

What the code does, in order

  1. Check the input: dates in the right order, no more than 7 days, none in the past.
  2. Notice a shared place name (for example Lapland) and ask which one you mean.
  3. Look the place up.
  4. Fetch the weather for your dates and a short description of the place, both at the same time.
  5. Choose forecast or the same dates last year, and build the packing list from rules.
  6. Build the card from Basic components and send it as an A2UI message.
  7. Your browser draws it with the official React renderer.

None of it needs a model. A model could be added at the front, to decide what to look up, or at the back, to word the result. The measured cost of the part we built is below.

The numbers

  • Text version: 32 parts, 2,736 bytes, with real checkboxes and buttons that send actions.
  • Picture version: 6 parts, 10,209 bytes: one Basic Image holding an SVG drawn by code and checked by a guardrail. Richer to look at, not interactive.
  • Server time: about 73 ms on a warm request, of which the weather and the place description together took 32 ms because they ran at once. Tokens: 0.

One request (Oslo, 3 days), one machine, measured on 2026-11-14. For comparison, the same weather card written by a model took 9.4 s and 10,570 input tokens in an earlier test (Express format, one run).

Questions

What is an A2UI example?

It is a screen an agent builds by sending A2UI messages, drawn by a renderer. This one is a trip planner: you say where you are going and on which dates, and the agent sends a card with the weather for those dates, a short description of the place and a packing checklist.

Is this built only from the Basic Catalog?

Yes. The text version uses 7 of the 18 Basic components (Card, Column, Row, Text, Divider, CheckBox and Button), 32 parts in one request. The picture version is one Basic Image holding a drawn SVG.

Does it use a language model?

No. A small program on a Worker validates the dates, asks which place you mean when a name is shared, looks the place up, fetches the weather and a description at the same time, builds the packing list from rules and builds the card. In the request we measured it used 0 tokens.

Is this official A2UI documentation?

No. A2UI is an open protocol created by Google. This page is an unofficial example written to help people build with it, and we are not affiliated with Google.

Where does the data come from?

Weather comes from Open-Meteo (CC BY 4.0), the place lookup from GeoNames (CC BY 4.0) through Open-Meteo's geocoding service, and the place description from the Wikipedia article (CC BY-SA 4.0). The credit travels inside each message. Dates beyond the 16-day forecast use the same dates last year, and the page says so.

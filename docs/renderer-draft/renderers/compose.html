Honest notes

  • Compose has no implementation of our atoms: every atom whose root is not a Basic component is not supported. Only atoms whose root type is a Basic component (Text, Column, Button, Tabs and so on) draw, through the Basic catalog.
  • Compose has no custom-atom implementations. 523 of the 551 stable atoms with an example are not supported; 28 draw natively only because their root is a Basic component. Say it plainly: this renderer is not a target for our atoms today.
  • Basic lane (the Basic catalog on its own): 670 of 670 cases render without error or crash; visible text is identical to React on 629 of 670 (514 of 551 among the stable atoms).
  • Behaviour, 48 Basic probes against React: same 33, different 10, same rejection 1, error 1, not runnable 3. Custom-atom behaviour probes were not run (the atoms are not registered).
  • Not run: dark mode, 360 px, an Android device or emulator, spec v1.0.
  • Pixel parity with React is not meaningful here (different fonts, Material 3 look), so the pixel lane is recorded for information and never decides a status.
